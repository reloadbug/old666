## 一、总览

把设计稿里的 6 大功能模块，拆成 **7 个阶段（P0–P6）**，每个阶段都能独立产出可体验版本。

| 阶段 | 主题 | 覆盖模块 | 规模 | 前置依赖 | 里程碑 |
|:---:|---|:---:|:---:|:---:|---|
| **P0** | 技术验证 PoC | — | S | 无 | M0 技术路线确认 |
| **P1** | 进程净化（MVP） | M2 | L | P0 | M1 可一键净化的可用版 |
| **P2** | 开机加速 | M1 | M | P1 | M2 开机耗时可视化 |
| **P3** | 场景模式引擎 | M3 | L | P1、P2 | M3 三套场景可切换 |
| **P4** | 一键体检 + 垃圾清理 | M4、M5 | M | P1 | M4 完整优化闭环 |
| **P5** | 监控悬浮球 + 打磨 | M6 | M | P1 | M5 Beta 版 |
| **P6** | 发布加固 | — | M | P5 | M6 1.0 正式版 |

**规模说明**：S = 单点验证，M = 一个完整功能页，L = 跨模块的完整子系统。

### 排序依据

1. **技术风险前置**：Win32 调用能力与打包体积是整个方案的地基，P0 必须先证伪/证实，避免后期返工。
2. **用户感知优先**：进程净化和开机加速是用户最能直接感受到价值的两个点，紧接 P0 之后做。
3. **差异化靠后**：场景模式是护城河，但它依赖 P1/P2 沉淀的进程与服务控制能力，故排 P3。
4. **每阶段可交付**：不做"半年后见"的大爆炸式开发，每阶段结束都有可运行版本。

## 二、阶段详情

### P0 · 技术验证（PoC）

**目标**：用最小代价证实「Rust + Tauri 2」能达成性能预算，并把不确认的技术点全部打掉。

**任务**

- [ ] 初始化 Tauri 2 + Rust 工程骨架（前后端打通、热重载可用）
- [ ] 接入 `windows-rs`，验证进程枚举（`NtQuerySystemInformation` / `EnumProcesses`）
- [ ] 验证 PDH 性能计数器采集 CPU / 内存 / 磁盘 / 网络
- [ ] 验证 UAC 提权后执行 `TerminateProcess` 的完整链路
- [ ] 验证 `EmptyWorkingSet` 内存工作集裁剪
- [ ] 测量打包体积与冷启动耗时，对照硬指标
- [ ] 输出 PoC 结论报告：确认技术选型，或提出替代方案

**交付物**：可运行的空白壳 + 进程列表 Demo + 性能基线报告

**验收标准**

- 便携包体积 **≤ 12 MB**
- 冷启动到可操作 **≤ 1.0 s**
- 能列出系统全部进程，并成功结束一个测试进程
- 采集 1000 个进程的资源数据耗时 **≤ 200 ms**

**风险**：WebView2 在部分老系统缺失 → 需评估内置固定版本运行时（会增大体积）或引导安装。

### P1 · 进程净化 MVP

**目标**：把产品最核心、也最需要判断力的能力做出来，验证"一键净化"的真实价值。

**任务**

- [ ] 进程列表页 UI（列表 + 资源列 + 分组头 + 多选）
- [ ] 资源采集与自适应刷新策略（1–5s 动态间隔）
- [ ] **闲置判定引擎**：6 维信号（活跃度 / 前台关联 / 使用频率 / 签名来源 / 系统关键性 / 用户白名单）
- [ ] 三档结论映射：可安全结束 / 建议保留 / 禁止结束
- [ ] 系统关键进程 · 服务 · 驱动硬编码黑名单
- [ ] 数字签名校验（`WinVerifyTrust`）辅助可信度判定
- [ ] 两段式结束：温和关闭信号 → 超时后强制结束
- [ ] 白名单与守护（用户标记保留的进程永久豁免）
- [ ] 操作快照记录 + 一键回滚
- [ ] 净化结果页（释放内存 / 结束进程数 / 可感知结论）

**交付物**：可一键净化的可用版本

**验收标准**

- 能安全结束 10+ 个闲置进程并真实释放内存
- **零误杀**：跑满 200 次净化测试，无一例结束系统关键进程或前台程序
- 净化耗时 ≤ 3 s
- 回滚成功率 100%

**风险**：误判导致用户程序异常 → 靠黑名单 + 白名单 + 快照回滚三重兜底。

---

### P2 · 开机加速

**目标**：让开机时间"可见、可解释、可缩短"。

**任务**

- [ ] ETW 开机阶段事件采集，归因到固件 / 内核 / 服务 / 启动项 / 桌面
- [ ] 开机时间线可视化组件（分段条形图 + 图例）
- [ ] 启动项枚举：注册表 Run 键 / 启动文件夹 / 计划任务 / 服务
- [ ] 风险分级规则库（安全禁用 / 谨慎 / 不建议）
- [ ] 禁用与延迟启动执行器
- [ ] 优化前后对比视图
- [ ] 历史开机耗时趋势记录

**交付物**：开机加速页

**验收标准**

- 时间线分段归因误差 < 10%
- 所有禁用项可一键还原
- 优化后开机时间有可测量的缩短

**风险**：ETW 需要管理员权限 → 提权动作走独立进程，不污染主 UI。

---

### P3 · 场景模式引擎

**目标**：落地差异化能力——一套规则引擎，驱动日常 / 游戏 / 服务器三套方案。

**任务**

- [ ] **规则 DSL 设计**：`条件 → 动作`，JSON/YAML 可读可编辑
- [ ] 规则引擎：匹配、编排、幂等执行、动作冲突处理
- [ ] 日常模式规则集（温和清理、80% 内存阈值、平衡电源）
- [ ] 游戏模式规则集（激进清理、60% 阈值、高性能电源、免打扰、前台优先级提升、网络优化）
- [ ] 服务器模式规则集（保守清理、90% 阈值、双确认、变更留痕、关键服务保护）
- [ ] 模式切换 UI + 每个模式的"会做/不会做"可解释说明
- [ ] 自动切换触发条件（可选，**默认关闭**）
- [ ] 自定义模式（高级设置）

**交付物**：三套可切换场景 + 规则引擎

**验收标准**

- 切换模式后系统行为与规则表逐条一致
- 服务器模式零误杀，所有变更可追溯
- 新增一个模式只需新增规则文件，不改代码

**风险**：模式之间动作冲突（如游戏模式提优先级 vs 服务器模式保稳定）→ 引擎需明确的优先级与互斥声明。

---

### P4 · 一键体检 + 垃圾清理

**目标**：给小白用户一个"打开就能用"的完整闭环。

**任务**

- [ ] 体检项定义与评分模型（0–100 健康分）
- [ ] 问题清单按影响大小排序
- [ ] 一键修复执行器（复用 P1/P2/P3 的能力）
- [ ] 内存工作集裁剪策略（阈值触发 + 手动触发）
- [ ] 垃圾文件扫描：临时文件 / 缓存 / 日志 / 回收站 / 更新残留
- [ ] 安全删除（走系统回收站机制，不做不可逆删除）
- [ ] 修复前后量化对比页

**交付物**：体检页 + 清理页

**验收标准**

- 体检全流程 ≤ 30 s
- 清理不触碰任何用户文档、照片、桌面文件
- 评分与实际系统状态正相关（可人工校验）

**风险**：垃圾文件误判 → 只清明确安全的目录白名单，其余一律不动。

---

### P5 · 监控悬浮球 + 打磨

**目标**：补齐常驻监控能力，并把体验和性能压到发布标准。

**任务**

- [ ] 悬浮球窗口（半透明 / 贴边收起 / 可调大小与透明度）
- [ ] 采样与阈值告警（轻提示，不打扰）
- [ ] 单击展开面板 / 双击唤起主界面 / 右键切换模式
- [ ] 全局动效打磨（圆环、进度、结果反馈）
- [ ] 性能压测与优化，逐项对齐硬指标
- [ ] 绿色便携版打包（解压即用，删除无残留）

**交付物**：体验完整的 Beta 版

**验收标准**

- 常驻内存 **≤ 40 MB**，常驻 CPU **≤ 0.5%**
- "用完即退"模式下常驻占用为 0
- 便携包解压即可运行，无需安装

---

### P6 · 发布加固

**目标**：从"能跑"到"敢发给陌生人用"。

**任务**

- [ ] 代码签名证书接入（消除 SmartScreen 警告）
- [ ] 自动更新机制（可关闭，默认仅提示）
- [ ] 服务器模式服务化（Windows 服务，无人值守守护）
- [ ] 本地崩溃收集与日志
- [ ] 兼容性矩阵测试（Win10 / Win11 / Server 2019+）
- [ ] 正式版发布与分发

**交付物**：1.0 正式版

**验收标准**

- 主流系统版本全部通过兼容性测试
- 安装/运行无安全软件误报
- 用户数据零外传（可用抓包自证）
