## 三、踩过的坑（重要，别再踩）

### 3.1 构建 / 打包

1. **前端资源被 brotli 压进 exe，改前端必须重编才生效。**
   `tauri_build::build()` 只对 `frontendDist` **目录**做 `rerun-if-changed`，
   Cargo 对目录只跟踪「增删文件」，**不跟踪目录内已有文件的内容修改**。
   → `src-tauri/build.rs` 已递归登记 `src/` 下每个文件。
   验证手法：解压 `target/<profile>/build/old666-*/out/tauri-codegen-assets/*` 后 grep（资产是 brotli 流，直接 grep 源码字符串无效）。
2. **`src-tauri/capabilities/` 必须存在。** 路径缺失时 Cargo 判定「永远脏」→ 每次构建全量重编 74 s。补 `capabilities/default.json` 后无改动构建 2 s。排查：`cargo build -v 2>&1 | grep Dirty`。
3. **`tools/run.ps1` 必须存 UTF-8 with BOM**，否则 PS 5.1 按 ANSI 解析，中文字面量全乱。
4. **PS 5.1 在 `$ErrorActionPreference='Stop'` 下，`cargo ... 2>&1` 会把 cargo 的 stderr 当成 NativeCommandError 抛出**（编译成功也报错），调用期间要临时降为 `Continue`。
5. **`cargo add` 在 PS 下常因 stderr 抛 NativeCommandError 被判 exit 1**，但其实已写入 Cargo.toml；`--offline` 时 cargo 给的版本建议可能过时，需与 `Cargo.lock` 里的 checksum 对齐后手工改写。
6. 运行中的 exe 会锁住 target 目录（`failed to remove file ... 拒绝访问 os error 5`）→ 用 `$env:CARGO_TARGET_DIR` 指向别处绕开。

### 3.2 ⭐ 项目目录被安全软件加了写入保护（2026-11-06 定位，最隐蔽）

**现象**：`cargo test` 里 8 个 `core::startup_ctl` 单测失败，报「被系统拒绝修改：该注册表启动项需要管理员权限，或被安全软件保护」。基线（未改代码）同样失败 → 一度以为是环境问题。

**排查过程**（方法值得复用）：
1. `whoami /all` → 确认是 `reloadbug\administrator`、高完整性级别、`BUILTIN\Administrators` 已启用。
2. PowerShell 里 `reg add HKCU\...\Run` **成功**；原生 `RegOpenKeyExW(sam=KEY_SET_VALUE)` 也返回 0。→ ACL 和 API 用法都没问题。
3. 写独立诊断 exe：**cargo 编译出的进程**里对 HKCU 的任何写操作都返回 `ERROR_ACCESS_DENIED(5)`，只读全 OK。
4. 决定性实验：**同一个 exe 复制到别处就正常**。
   - `D:\AI game\old666\...exe` → DENY
   - `D:\AI game\`、`D:\`、`C:\Users\Administrator\`、`%TEMP%` → OK
5. 结论：**`D:\AI game\old666\` 目录被安全软件（360 系）加了目录级写入保护策略**，只拦截「从该目录启动的进程」的注册表/文件写入，与权限、API、令牌无关。

**规避**：测试与构建产物放到项目目录之外：
```powershell
$env:CARGO_TARGET_DIR='D:\tmp_probe_target'
```
之后 `cargo test` → **178 passed / 0 failed**，基线恢复全绿。

> 教训：断言失败信息里的「需要管理员权限」**可能是在撒谎**——它只是把 `raw_os_error()==5` 翻译成了人话。下次遇到，先做「换个目录跑一遍」这个对照实验。

### 3.3 WebView2 / GUI

- 启动报 `WebView2 error: HRESULT(0x800700AA) "请求的资源在使用中"` → **WebView2 用户数据目录被占用**，与代码改动无关（用已发布的老 exe 也能复现）。
  解法：设 `$env:WEBVIEW2_USER_DATA_FOLDER=<独立空目录>`（改 LOCALAPPDATA/APPDATA 无效）。

### 3.4 开机加速 / 启动项

- `WOW6432Node\…\Run` 的启用状态在 **`StartupApproved\Run32`** 而非 `Run`；新增 `startup::approved_leaf(subkey)`，扫描与 `approved_target` 共用。
- 真实系统里 **95 个自动服务有 23 个受保护**（RpcSs / DcomLaunch / mpssvc / Schedule / Defender Core …），连管理员都拿不到 `SERVICE_CHANGE_CONFIG`。
  → 必须**在演练阶段就 `probe_writable`**，别等用户点确认才撞 `ERROR_ACCESS_DENIED`。
- 601 MB 级的签名哈希是磁盘 I/O 瓶颈，加线程反而更慢（8 线程 2.1 s vs 单线程 0.6 s）→ 走两段式（快速扫描 154 ms + 按需补签 745 ms），用等价性测试 `fast_then_verify_equals_deep` 兜底。

### 3.5 前端 / CSS

- **`[hidden]` 被作者样式 `display` 盖掉** 是会反复咬人的一类坑：`.drawer{display:flex}`、`.btn{display:inline-flex}` 各咬过一次（抽屉常驻吃点击、该藏的按钮没藏）。已在根部统一 `[hidden]{display:none !important}` + 回归断言。

### 3.6 工具链 / 沙箱

- 沙箱不允许 node `child_process.spawnSync` 起进程（EBUSY）→ fixture 生成走 `tests/gen-fixtures.sh`（bash），node 只读 fixture 驱动浏览器。
- `Add-Type` 在沙箱被拦；`Compress-Archive` 产出的反斜杠 zip 用 `Expand-Archive` 解。
