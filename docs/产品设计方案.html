01

产品定位与痛点

先想清楚「不打谁、替谁解决什么」，再谈功能。老六清净的对标不是功能数量，而是「克制」。

1.1 用户真实痛点

痛点 A · 开机慢

装了太多软件后，开机项、计划任务、服务层层叠加，开机 1 分钟起步，却不知道到底是谁拖的。

痛点 B · 久用卡顿

开机几小时后内存被各种后台进程、缓存、更新程序吃掉，切窗口、开浏览器都发涩。

痛点 C · 不知道该关谁

任务管理器能看进程，但普通用户分不清哪个能关、哪个关了会出问题，不敢下手。

1.2 现有工具的「原罪」

  • 广告与营销：首页一半是推广位，清理完弹窗推软件，把工具做成流量入口。
  • 重后台：常驻进程 200–500 MB，安全模块、升级模块、推广模块全在跑，本身就制造卡顿。
  • 捆绑与全家桶：装一个带一串，卸载还留残留。
  • 黑箱操作：一键优化后改了哪些设置、能不能回滚，用户完全不知道。
  • 专业工具门槛高：Process Lasso / Process Explorer 能力很强，但界面面向工程师，普通用户看不懂。

1.3 差异化定位

维度传统安全卫士老六清净 old666
广告多（首页 + 弹窗 + 推送）零广告、零弹窗、零推送
常驻占用200–500 MB，多进程常驻< 40 MB，可设「用完即退」零常驻
安装方式强安装 + 捆绑绿色便携单目录，可直接删
操作路径多级营销页面一屏一焦点，一键完成
数据隐私行为上报、云端规则纯本地决策，默认不联网
可解释性黑箱优化每步可解释、可回滚
一句话定位：把「开机加速 + 进程净化 + 场景调优」这三件事做到极致，其余全部砍掉。 做系统工具里的「极简主义」——功能少一点，但每一点都让人放心。
02

核心功能规划

六大模块，其中 M2 进程净化与 M3 场景模式是产品护城河，其余为配套。

2.1 功能全景

M1

开机加速

让开机时间可见、可解释、可缩短

  • 开机耗时时间线分析（BIOS→系统→服务→启动项→桌面）
  • 启动项 / 计划任务 / 服务 / 驱动 四类统一管理
  • 风险分级建议：安全禁用 / 谨慎 / 不建议
  • 延迟启动（开机 2 分钟后再拉起）
M2 · 核心

进程净化

找出「用不上却占资源」的进程并安全清理

  • 实时进程资源视图（CPU / 内存 / 磁盘 / 网络 / GPU）
  • 不常用进程识别（使用频率 + 活跃度 + 关联程序状态）
  • 智能分组：可安全结束 / 建议保留 / 系统关键
  • 一键净化 + 白名单守护，杜绝误杀
M3 · 差异化

场景模式

一套策略引擎，适配不同使用场景

  • 日常模式：均衡，保留常用后台
  • 游戏模式：极致释放，降干扰
  • 服务器模式：稳定优先，保守回收
  • 支持自定义模式与自动切换触发条件
M4

一键体检

小白入口：扫描 → 评分 → 一键优化

  • 30 秒快速体检，输出健康评分
  • 按「影响大小」排序的问题清单
  • 一键修复 + 修复前后对比
M5

内存与垃圾清理

只清理真正能安全回收的东西

  • 内存工作集裁剪（EmptyWorkingSet 策略化）
  • 临时文件 / 缓存 / 日志 / 回收站 / 更新残留
  • 大文件与重复文件扫描（可选）
M6

实时监控

轻量悬浮球，一眼看清机器状态

  • 桌面悬浮球：CPU / 内存 / 温度 / 网速
  • 点击展开极简面板，长按唤起主界面
  • 阈值告警：资源异常时轻提示，不打扰

2.2 核心功能深挖 · 进程净化

这是最需要「判断力」的模块。普通用户不敢关进程，是因为怕关错。老六清净的价值 = 替用户做安全判断，并说清理由。

判定维度信号结论倾向
活跃度近 30 分钟无 CPU / IO / 网络活动偏「可清理」
前台关联不属于任何可见窗口 / 前台程序偏「可清理」
使用频率本地统计该进程近 7 天从未被用户主动使用偏「可清理」
签名与来源是否有有效数字签名、是否为已知系统组件签名可信 → 偏「保留」
系统关键性命中系统关键进程 / 服务 / 驱动清单强制「禁止结束」
用户白名单用户曾标记保留强制「保留」
安全红线：系统关键进程、安全软件、杀软/EDR、正在写入的数据库、当前前台程序的子进程， 一律进「禁止结束」黑名单，永不参与一键净化。任何结束动作前先记录快照，支持一键回滚。

2.3 「一键净化」的执行策略

  • 两段式：先「温和结束」（发送关闭信号，给程序自己退出的机会），失败再「强制结束」。
  • 分组执行：按进程组（同属一个父进程 / 同一软件）整体处理，避免只关一半导致重启。
  • 可回滚：记录被结束进程的路径与启动命令，一键「恢复上次净化」。
  • 结果可读：净化后直接给出「释放内存 1.8 GB / 释放 12 个进程 / 预计降温 4℃」这类可感知结论。
03

场景模式设计

模式 = 一组可解释、可编辑的策略。用户切换的是「意图」，系统翻译成「动作」。

3.1 三套内置策略对比

策略项日常模式游戏模式服务器模式
核心目标均衡流畅极致性能释放稳定不间断
后台进程清理明确闲置项激进清理非必要后台保守，仅清理明确无害项
内存回收阈值 80% 触发阈值 60% 触发，主动释放阈值 90% 触发，避免抖动
电源计划平衡高性能 / 卓越性能高性能（可锁定）
通知与弹窗正常免打扰 / 全屏抑制正常（保留告警）
进程优先级默认提升前台游戏优先级保障关键服务优先级
网络优化默认降低游戏延迟 / QoS 优先保持长连接稳定
Windows 更新正常暂停（游戏期间）可控窗口期更新
日志与监控关闭关闭开启，资源与进程留痕
误杀风险低中（有白名单兜底）极低（双确认）

3.2 模式引擎的关键设计

规则驱动，而非硬编码

每个模式是一份 JSON/YAML 规则集（条件 → 动作），引擎统一执行。 新增模式 = 加一份规则，不改代码；用户也能在高级设置里微调。

自动切换（可选）

检测到全屏 3D / 游戏进程启动 → 自动切游戏模式；检测到服务器服务角色 → 建议切服务器模式。 默认关闭，避免「自作聪明」。

服务器模式的双保险

任何结束动作二次确认 + 关键服务白名单 + 变更留痕。宁可少优化，也绝不动到业务进程。 可选以 Windows 服务形式运行，实现无人值守守护。

模式可解释

每个模式页直接列出「会做哪些事、不会做哪些事」，用户一眼看懂切换的代价，不做黑箱。

04

UI / 交互设计方案

设计目标：清新、克制、一看就懂。把「信息层级」做对，用户就只需要做决定，不需要做研究。

4.1 四条交互原则

① 一屏一焦点

每页只突出一个主操作按钮，其余降级为辅助信息。

② 一点就搞定

主要优化都收敛为一个大按钮，默认参数即最佳实践。

③ 渐进披露

默认只看结论，想深究再展开细节，不吓退小白。

④ 即时反馈

每个动作都有过程动画 + 结果量化，让用户「感觉有效」。

4.2 品牌标志（Brand Mark）

产品标志由用户商标（兽首轮廓 + 赤红双眼）矢量化重建，形状 100% 保留， 与青绿渐变英文名组成横版组合标。

配色分工：标志黑红 · 界面青绿。 双眼保留赤红作为全案唯一暖色点缀，界面主色青绿留给 UI，既有商标记忆点，又保持产品清新调性。

完整规范（4 种配色 / 组合标 / 应用图标 / 使用禁区）见 assets/logo/showcase.html

  • 字体：系统默认中文字体 + Segoe UI；正文 14–15px，标题 700–800 字重
  • 圆角：卡片 16px / 按钮 12px / 小控件 8–10px，统一圆润语言

  • 评分圆环：数字滚动 + 环形生长，200–600ms

  • 全局：所有动效 ≤ 300ms（扫描类除外），绝不拖慢操作

05

技术架构设计

技术选型的第一原则是「轻」：体积小、启动快、常驻低。第二原则是「安全」：所有系统操作可控可回滚。

5.1 技术选型对比

方案体积启动内存开发效率评价
Rust + Tauri 2~8 MB极快低中 推荐。Rust 直调 Win32 性能最好，WebView2 做 UI 易出好界面，产物极小、天然便携。
C# .NET 8 + WinUI 3~40 MB快中高 备选。Windows API / WMI 生态最成熟，开发最快；体积与内存略大，AOT 可优化。
C++ / Qt~15 MB快低低 性能最优但 UI 开发慢、迭代成本高，适合后期对性能极致压榨时局部替换。
Electron>120 MB慢高高 不满足「轻量化」定位，排除。
结论：采用 Rust 核心 + Tauri 2（前端 WebView2）。 前端用 HTML/CSS/TS（可配 Svelte/Vue 轻量框架）负责「好看好改」，Rust 负责「所有系统级动作」，两者通过 Tauri IPC 通信。

5.4 安全设计

权限模型

  • 主程序以普通权限运行，仅在需要时通过 UAC 提权执行特定动作
  • 提权动作单独进程执行，主 UI 不被污染
  • 服务器模式可选注册为 Windows 服务，实现无人值守

防误杀

  • 系统关键进程/服务硬编码黑名单，永不参与清理
  • 数字签名校验（WinVerifyTrust）辅助判定可信度
  • 前台程序及其子进程自动豁免
  • 所有结束动作先记录快照，可一键回滚

隐私

  • 默认不联网，规则与统计全部本地化
  • 如需更新规则，采用匿名、可关闭的拉取
  • 不采集用户文件内容、不记录浏览行为

稳定性

  • 所有系统调用错误可恢复，不因单点失败崩溃
  • 看门狗线程保障监控不中断
  • 资源采样采用增量与缓存，避免高频轮询拖慢系统

指标目标说明
安装包 / 便携包体积≤ 12 MB不含运行时依赖，WebView2 走系统自带
冷启动到可操作≤ 1.0 s懒加载非首屏模块
后台常驻内存≤ 40 MB悬浮球模式；「用完即退」模式为 0
常驻 CPU 占用≤ 0.5%采样间隔自适应（1–5s）
一键净化耗时≤ 3 s并发处理 + 两段式结束
06

开发顺序与路线图

原则：先把最核心、最难、最能验证定位的能力做出来，再堆外围。宁可少功能，不可晚交付价值。

P0

技术验证（PoC）

验证 Rust 直调 Win32 的可行性：进程枚举 + 资源采集 + 安全结束 + Tauri 打包体积/启动耗时。

交付：可运行的最小壳 + 性能达标结论（决定是否继续 Tauri 路线）
P1

MVP · 进程净化

进程列表 + 资源视图 + 智能分组 + 一键净化 + 白名单 + 回滚。这是产品价值的核心验证点。

交付：能用「一键净化」真实释放内存的可体验版本
P2

开机加速

开机时间线采集、启动项/服务/计划任务管理、风险分级、延迟启动。

交付：开机耗时可视化 + 可安全缩短开机的优化项
P3

场景模式引擎

规则引擎 + 日常/游戏/服务器三套预设 + 模式切换与自动触发（可选）。差异化能力落地。

交付：可一键切换的完整场景方案
P4

一键体检 + 垃圾清理

健康评分、问题清单、一键修复；内存裁剪与垃圾文件清理。

交付：小白用户可独立完成的完整优化闭环
P5

监控悬浮球 + 打磨

悬浮球、告警、动效打磨、性能压榨、绿色便携版打包。

交付：体验完整、体积与性能达标的 Beta 版
P6

发布与加固

代码签名、自动更新（可关）、服务器模式服务化、崩溃收集（本地）、正式版发布。

交付：可正式对外分发的 1.0

6.1 优先级判断依据

排序依据说明
用户感知强度「一键净化」和「开机加速」是用户最直观能感受到价值的，优先做。
技术风险前置Win32 调用与 Tauri 打包体积是最不确定的部分，必须在 P0 验证，避免后期返工。
差异化能力场景模式是区别于传统卫士的关键，但依赖进程与服务的控制能力，故排在 P3。
可交付性每个阶段都能独立出可体验版本，便于尽早验证和收集反馈。

6.2 后续可扩展方向（非首版）

  • 进程级网络流量监控与限速
  • 驱动/固件更新提醒（只提醒，不代装）
  • 多机批量管理（面向小团队 / 网吧 / 服务器群）
  • 可选的规则市场（用户分享场景规则，纯社区、无广告）
